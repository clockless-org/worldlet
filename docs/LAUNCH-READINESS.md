# Launch readiness

Acceptance follows the current product promise and exact distributed build. Old
release numbers, completed tours and retired model fallbacks are not today's gates.
The product blueprint tracks capability-level gaps; release
Issues record concrete host/account evidence.

## Small invited test: required loop

Install → enter the world → chat with Fox → connect a real source → receive grounded
Attention → open the original and act. A partial or assisted test must be described as
such; nothing in this checklist declares the product ready by itself.

| Gate | Required evidence |
| --- | --- |
| Installation and restart | Exact distributed artifact starts without developer tools; restart preserves records |
| Current onboarding | Google authorization, cancellation/retry, Applet choices and first entry work for a new user |
| Fox | Included or supported user model gives a real response; failure, continued input and recovery are clear |
| Sources | At least one promised external source connects, reads, disconnects and reconnects on a non-team account |
| Attention | Useful distinct obligations, accurate originals, no duplicate nagging, completion retained after restart |
| Applet loop | Enter, inspect, read, Fox action and Back work; website exit stops media |
| Support | Version, useful redacted diagnostics, contact path and honest limits are available |

Manual updates are acceptable only if explicitly part of the test promise. Do not
require every catalog website to be a fully integrated native Applet before testing
the core loop. Voice may remain limited if text and recovery work and the limit is clear.

## Before unassisted public promotion

- Verify clean supported machines and the update/data-preservation path for each
  advertised platform. Platform-specific evidence is not transferable by assumption.
- Finish relevant provider authorization/distribution reviews. A working developer
  account or public endpoint is not public OAuth approval.
- Review privacy, model costs, source bounds, deletion/backup semantics and support
  instructions against the actual release. Publish disclosures before expanding data use.
- Validate multi-day source usefulness, interruption/recovery and external action outcomes.
- Audit shipped dependencies/licenses, signed distribution identity and recovery procedure.
- Promise only accepted capabilities; website launch, source sync and task execution are
  separate acceptance scopes.

## Evidence rules

Record source revision, artifact identity, host/OS, tested scenario and limitations in
the release or acceptance Issue. Do not regenerate a growing per-build docs directory.
A green fixture suite cannot substitute for real permissions, account contents or
human assessment of relevance. Incomplete checks remain explicit.
