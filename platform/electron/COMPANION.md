# Desktop Companion

Closing or minimizing the World window, or another app coming to the foreground, is a presentation change, not an Agent/session boundary. Each moves the existing live World `WebContentsView` out of the World window into a transparent, frameless, always-on-top window (a macOS `panel` that stays on every Space and over full-screen apps). No second page, Agent, storage profile or conversation is created. The view keeps its original viewport size: the native window is cropped around the measured Companion cluster instead of resizing the page. Fox, the action dock, panel button, status/input strip and reply keep their original elements and shared CSS. Desktop CSS only hides the surrounding world and makes its background transparent; it must not introduce separate HUD sizing or responsive rules. Quitting Worldlet still stops the store and Agent runtime normally.

Whenever the World window is not in front, Fox floats on top (owner Order 2026-10-09): when the World window loses the foreground to another app (Mac: the app resigns active; every OS: the World window blurs), Fox moves to the desktop 150ms later unless a Worldlet window has the foreground by then (focus moving to a Worldlet task page, browser window or the Companion itself never moves Fox). The World window stays where it is and shows the world's last frame without Fox (`worldletCompanionBackdrop` hides the cluster for that capture), so the person sees an unchanged World behind the other app; it keeps its taskbar button, so Windows adds no tray icon unless the World is later closed. Focusing the World window again (clicking it, the Dock or taskbar button, Command/Alt-Tab) brings Fox back into it; the last frame stays above the returning page until it has painted. Fox stays in the World while a website, a video or a call is open there, because moving the view would close them; during onboarding; while the World page is still starting (`worldletCompanionGeometry(true)` refuses); and in checks and background launches (`--check`, smoke, RC check, `WORLDLET_BACKGROUND_WINDOWS`), whose windows rarely hold the foreground. A native dialog attached to the World (backup, diagnostics export) blocks detachment until it closes. Generation checks discard cancelled close/minimize/deactivation callbacks.

- One message bar sits under Fox (owner decision 2026-10-04, like Claude's composer): the field, then the microphone and Send inside it. The bar has two sizes (owner Order 2026-10-08): 200px until it is focused (272px in a website, where it also takes a web address) and 360px while typing. At rest it is low-key (owner request 2026-10-05): faint, saying only “Message Fox”; pointing at the bar or Fox brightens it with “Click to type · hold to speak” (on touch “Tap…”) without changing its size, and Send shows only once there is something to send; a click starts typing and opens it to 360px, a stationary 280ms hold on it speaks instead. Clicking Fox does the same as clicking the bar (owner feedback 2026-10-04): it starts typing. The buttons beside Fox share one style, a frosted capsule with an icon and its name, at most three a side, stacked top to bottom and centered on Fox (owner requests 2026-10-05); on the left, Settings, then Order under it in Alpha and Dev. **Settings** opens the centered Companion Panel straight on its Settings tab (owner Order 2026-10-07; the tutorial's on/off switch is in the World's top-right corner); hold Fox to speak and release to finish. Send is an icon the same size and style as the microphone. The microphone supports click-to-record and hold-to-speak. On the desktop, opening the panel first restores World. Thinking displays three dots above Fox; active work and transcription display a short status there. Reduced motion keeps the dots static. The same built-in Fox artwork and reply paper are used.
- Only the lower Companion cluster is portable: Fox, its message bar (plus the desktop return icon), reply (which also carries notices) and side actions. Global titles, Attention Center and other world chrome stay in World. The page reports the cluster's bounds (`desktopCompanionSize`) and the window follows them, including replies, by moving only the native crop; the page stays fixed in screen coordinates. There are no fixed compact/expanded window sizes or invisible drag handles. Moving Fox more than 12 CSS pixels before the hold threshold drags the cluster and cancels speech activation; a stationary 280ms hold starts speech. While dragging, the host moves the window with the screen cursor (`desktopCompanionDrag`), which avoids feedback jumps. The chosen World position persists across Applets and restarts, with no reset-to-origin action.
- Back to World is a small round icon left of the bar, not a large smart action; it shows only on the desktop. The bar's width change takes 220ms; reduced motion skips it. The field is a text area that grows upward with the draft, up to six lines, then scrolls; Fox and its reply rise by the same amount. Enter sends, Shift-Enter starts a new line, and Enter that confirms an input-method candidate does not send. A field with a draft stays in typing when focus leaves it (a stray click while selecting text, owner report 2026-10-04); Escape or sending returns the bar to rest, and an empty field returns to rest when focus leaves. Content actions such as View event and reply navigation (`openWorld`) wait for the World window and page presentation to return before navigating. Failed restoration leaves the desktop context in place instead of navigating hidden content. Inline media actions can remain on the desktop.
- Back to World, **Open World** (Command/Ctrl-1), restoring the minimized window, focusing it, clicking the Dock icon or launching Worldlet again moves the view back into the World window.
- Closing the window leaves background work running. Right-click Fox (or the Dock icon on Mac) for Back to World and Quit Completely. The app menu labels Command/Ctrl-Q as Quit Completely; explicit termination still shuts down the runtime normally. On Windows, right-clicking the taskbar button also offers Quit Worldlet (a Jump List task that launches the app with `--quit`; the running copy quits), since that menu's Close window only closes the World. Quitting hides Fox and the World at once, gives quit work four seconds, then ends every process the app spawned that is still running, with its children, before exiting ([`src/host/quit.ts`](src/host/quit.ts); owner report 2026-10-04: Fox stayed on the desktop after quitting). The Windows update installer is the exception: it waits for that quit to replace the app (`outliveQuit`). The first time after setup that Fox lands on the desktop, it says so once in its reply place (fading after 15 seconds): it keeps working in the background, and right-clicking it or the Dock (Windows: tray) icon goes Back to World or Quits Completely (`ui/onboarding/desktop-companion-hint.ts`, remembered in the page's storage).
- The current environment becomes Desktop Companion; hidden Applet/browser content is not represented as visible desktop content. No screenshot or desktop-reading permission is added. Explicit navigation tools reopen the world.
- Website views and the inline player stop before the view leaves the World window, and browser/picture-in-picture requests are ignored while detached. The exception is Fox's own page in its task picture-in-picture window, or one Fox is driving: it shows in a window of its own beside the Companion, and Fox keeps working ([task picture in picture](../browser/INTEGRATION.md#task-picture-in-picture), #1175). Background checks and foreground Agent work retain their existing lifecycle.
- Until onboarding is over (setup, then the first-run tour and first task, `onboardingUnfinished` in `core/onboarding`), Fox never stays on the desktop (owner request 2026-10-04): closing the World window quits Worldlet and minimizing only minimizes. The next launch resumes setup or the tour where the person left it. Skip tutorial ends the tour, and from then on closing keeps Fox on the desktop.
- Opening an OAuth browser leaves the login page intact: loss of focus never detaches during onboarding or before the World has its Companion, and the setup fallback is only for explicit close/minimize.

The same code runs on every OS. Before #996 this policy existed only on Mac (Windows closed the app with its window). On Windows the hidden World has no taskbar button, so while Fox is on the desktop a notification-area (tray) icon is the way back: clicking it or its Back to World item restores the World, Quit Completely quits, and the icon goes when the World returns (#1026). Mac keeps its Dock menu; Linux adds no icon. The Windows tray way back was checked on a Windows 11 device for #1026; Windows 11 first places a new icon among the hidden icons (the ^ flyout) until the user pins it. Other Windows and Linux Companion behavior has not been accepted on a device.

## Ownership

[`src/modules/shell/companion.ts`](src/modules/shell/companion.ts) owns detaching and reattaching the view, the floating window, the crop, dragging and restoration; [`src/modules/shell/index.ts`](src/modules/shell/index.ts) registers its page actions and the Back to World / Quit Completely menus, [`src/modules/shell/companion-tray.ts`](src/modules/shell/companion-tray.ts) owns that shared menu and the Windows tray icon, and the World window's close hook asks it whether to keep the app open. `ui/companion/desktop-companion.ts` and its stylesheet own presentation, with context handling in the existing Companion module.

## Focused checks

After `npm run build:native-ui`:

- `node scripts/desktop-companion-ui-check.ts`: real bundled UI with a fixture bridge; type/reply, compact geometry, context isolation and failed/retried World restoration.
- `node scripts/desktop-companion-root-check.ts` and `node scripts/companion-main-session-check.ts`: Companion root presentation, shared main conversation and late-reply isolation.
- `npm run test:electron`: the host contract confirms the Companion actions are registered and the smoke run answers `desktopCompanionState`; `module:modulesshell` detaches and restores real windows and checks the Windows tray icon (added on detach, one at a time, removed on restore, Quit Completely) and the move when another app comes to the front (held during onboarding, for another Worldlet window and for open websites; the World window stays visible; focus brings Fox back). Real OS foreground changes on Mac and Windows have not been accepted on a device.

The native-window cycle (close/reopen, minimize/restore, same page, focus, drafts, unchanged viewport and screen coordinates while the crop grows) was checked by the retired Swift host's `--desktop-companion-check`; that check has not been ported to Electron. The fixtures do not establish live microphone transcription or real-account behavior.

Historical native-host repair and verification journals are in the prior record and Git history.
